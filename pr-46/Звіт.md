# Практична 46 Обробка помилок клієнта PostService

Реалізовано IPostServiceClient і PostServiceClient з методами для GET /postings, GET /postings/{id}, POST /postings, PUT /postings/{id} та DELETE /postings/{id}. HTTP транспорт створюється у Program.cs і передається клієнту. Форми PostingList та PostingEdit залежать від IPostServiceClient; прямих HTTP запитів у них немає.

## Перетворення відповідей у винятки

EnsureSuccessAsync пропускає успішні відповіді. При 400 читає власний ValidationErrorResponse й генерує PostingValidationException зі словником Errors. Інші неуспішні HTTP відповіді перетворюються на HttpRequestException зі збереженим StatusCode. Недоступний сервер не має HTTP статусу. Тайм-аут без скасування з боку виклику також подається як HttpRequestException без статусу; явне скасування CancellationToken залишається скасуванням.

| Ситуація | Перевірений результат клієнта | Реакція обробника форми |
|---|---|---|
| Сервер недоступний | HttpRequestException, StatusCode = null | Діалог Повторити або Скасувати; повтор повертає до операції, скасування залишає вікно доступним |
| Запис відсутній | HttpRequestException, StatusCode = 404 | Повідомлення про відсутній запис та оновлення списку; діалог редагування закривається, якщо запис зник після його відкриття |
| Некоректний відправник і нульова вага | PostingValidationException, помилки From та Weight | Пояснення й ErrorProvider біля полів; вікно редагування залишається відкритим |
| Сервер повернув 500 | HttpRequestException, StatusCode = 500 | У формі не перехоплюється; глобальний обробник повідомляє про непередбачену помилку й завершує застосунок |

Для 400, 404 і 500 виконано фактичні HTTP запити до включеного сервера та перевірено типи винятків PostServiceClient. Також перевірено справжнє з’єднання до зупиненого сервера, тайм-аут і явне скасування. На запущеній формі підтверджено діалог «Сервер недоступний» із кнопками «Повторити» та «Скасувати»; після скасування кнопки головної форми знову доступні. Створення, читання, редагування, видалення та отримання переліку пройшли інтеграційну перевірку. Файл http-requests.rest містить відповідні запити. Реакції форм для решти ситуацій описано за реалізованими обробниками; повний візуальний прогін ПР-46 не виконувався через недоступність захоплення Windows в поточному середовищі.

## Глобальна обробка

У Program.cs зареєстровано Application.ThreadException для помилок потоку інтерфейсу й AppDomain.CurrentDomain.UnhandledException для необроблених винятків інших потоків. ExceptionLog розгортає TargetInvocationException і формує запис із часом, типом, повідомленням, стеком та вкладеними причинами. Запис надходить у Debug.WriteLine. Користувач бачить лише загальне повідомлення без стеку та імен внутрішніх класів.

Після непередбаченої помилки UI викликається Application.Exit. Подія UnhandledException не використовується як спосіб відновлення: фатальна помилка іншого потоку завершує процес засобами runtime. Формат журналу та розгортання вкладеного винятку перевірено окремо.

Форми обробляють лише помилки з відомою дією: повторити, виправити введення або оновити дані. Перехоплення всіх Exception у формах приховало б програмні дефекти й дозволило продовжити роботу в невідомому стані. Розблокування кнопок розміщено у finally, тому відома помилка не залишає інтерфейс заблокованим.
